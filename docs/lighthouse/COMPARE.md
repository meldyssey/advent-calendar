## 분석

### 긍정적 변화
- **모바일 메인 CLS 0.121 → 0.021** — 가장 큰 개선. lazy loading으로 인증 상태 렌더링 순서가 바뀐 효과로 추정
- **모바일 프로젝트 목록 LCP -1.0s / TTI -0.9s** — 코드 스플리팅의 직접적 효과
- **모바일 메인 성능 점수 +7점, 프로젝트 목록 +4점**

### 제한적 개선 / 하락 원인 분석
- **데스크탑 메인 CLS 0.051 → 0.122 악화** — 모바일 메인 CLS가 개선된 것과 반대. lazy loading 이후 인증 상태 전환 시 데스크탑에서는 오히려 레이아웃 이동이 증가한 것으로 추정
- **데스크탑 로그인·프로젝트 생성 LCP/TTI +0.3s 증가** — 청크 분리 후 병렬 요청 증가로 인한 네트워크 오버헤드 추정. 데스크탑은 단일 큰 번들이 오히려 유리할 수 있음
- **모바일 프로젝트 생성 LCP/TTI +0.8s 악화** — lazy load 청크 로딩 시 추가 레이턴시 발생. 첫 방문 시 청크 캐시가 없는 상태에서 측정된 결과
- **FCP 전 페이지 변화 없음** — FCP는 JS 번들 크기보다 초기 HTML/CSS 로딩에 의존하므로 코드 스플리팅의 영향 범위 밖
- **로그인 CLS 개선 미미** (모바일 0.15 → 0.146, 데스크탑 0.124 → 0.122) — 번들 최적화와 무관한 인증 상태 UI 처리 문제로 별도 개선 필요

### 측정 한계
- Lighthouse 모바일 시뮬레이션 특성상 ±5점 내외 편차 존재
- 청크 캐싱 효과는 **재방문** 시에 극대화되나, Lighthouse는 항상 cold start 기준 측정
